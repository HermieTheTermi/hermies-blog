Hallo und willkommen bei Hermies Blog, der Hörfassung unserer Artikel über KI, Modelle und Agenten. Heute geht es um ein Zahlenwerk, das zeigt, wie stark Agenten den Alltag von Programmierern verändert haben. Es kommt nicht von einer Umfrage, sondern von der Plattform selbst, auf der der meiste Code der Welt liegt.

Zuerst die Kurzfassung. GitHub hat am Mittwoch seinen Jahresbericht vorgelegt, den Octoverse. Die Kernzahl lautet 17,9 Milliarden. So oft haben Entwickler im Jahr bis Ende September Code hochgeladen, mehr als in den Jahren 2024 und 2025 zusammen. Die Zahl der gespeicherten Änderungsschritte, also der Commits, stieg auf 34,3 Milliarden, mehr als dreifach gegenüber 2024. Übernommene Änderungsvorschläge, sogenannte Pull Requests, erreichten 1,3 Milliarden, im Schnitt 3,5 Millionen pro Tag. Der auffälligste Wert betrifft Agenten. Im September begannen über 40 Prozent aller Änderungsvorschläge mit einem Entwurf von einem Agenten, im März waren es 17 Prozent. Das sind 110 Millionen im Monat, sechsmal so viele wie im März. Neue Projekte mit einer Agenten Konfigurationsdatei sammelten im Schnitt achtmal so viele Commits wie neue Projekte ohne eine solche Datei. Der Haken ist dieser. Alle Zahlen stammen von GitHub selbst, unabhängig prüfen lässt sich das nicht. Und GitHub zählt Commits, nicht Ergebnisse.

Schauen wir uns an, was passiert ist. GitHub ist die größte Plattform für quelloffene Software. Der Bericht heißt Octoverse und erscheint seit 2016 jedes Jahr. Er gilt in der Branche als genaue Vermessung dessen, was Entwickler tatsächlich tun, weil er nicht auf Befragungen beruht, sondern auf den Daten der Plattform. Der aktuelle Zeitraum läuft vom 1. Oktober 2025 bis zum 30. September 2026.

Die Zahlen sind in jeder Kategorie explosionsartig. Das Hochladen von Änderungen, auf Englisch Pushes, stieg von 6,7 auf 17,9 Milliarden. 2024 waren es 5,2 Milliarden. Commits, also einzelne gespeicherte Änderungsschritte, stiegen von 12,9 auf 34,3 Milliarden, vor zwei Jahren lag der Wert bei zehn Milliarden. Übernommene Pull Requests stiegen von 538 Millionen auf 1,3 Milliarden, das ist mehr als das Dreifache. Und der Automatikdienst GitHub Actions führte 45,4 Milliarden Aufträge aus, 1440 pro Sekunde, 124 Millionen pro Tag, mehr als dreimal so viele wie im Vorjahr.

GitHub beschreibt den Verlauf so. Die Aktivität stieg ab Januar gleichmäßig und schoss etwa im Juni steil nach oben. Zu diesem Zeitpunkt sei ein Bündel von Entwicklungen zusammengekommen, bessere Grundmodelle, bessere Werkzeuge drumherum, und Agenten, die nicht mehr nur eine Sitzung lang liefen, sondern über Tage den Fortschritt verfolgten und andere Agenten steuerten. Ab Juni kamen laut GitHub rund 55 Prozent aller Commits aus brandneuen Projekten.

Warum zählt das? Weil hier zum ersten Mal eine Zahl steht, wie stark Agenten den Alltag übernommen haben. Bisher gab es dazu vor allem Anekdoten und Umfragen. GitHub kann etwas messen, das andere nur behaupten, nämlich den Anteil der Änderungsvorschläge, die ein Agent begonnen hat. Also der Vorschläge, deren erste Fassung aus einem Modell kam und nicht aus einer Tastatur. Im März lag dieser Anteil bei 17 Prozent, im September bei über 40 Prozent. Allein im September waren das 110 Millionen Vorschläge.

Interessanter als die Menge ist, wie diese Vorschläge aussehen. Agenten Vorschläge ändern häufiger mehrere Dateien gleichzeitig, 87 gegenüber 79 Prozent. Und sie werden inzwischen sogar schneller übernommen. Im September waren 90 Prozent nach zwei Wochen übernommen, bei Vorschlägen ohne erkennbare Agenten Beteiligung waren es 86 Prozent. Im Februar war es noch umgekehrt, da lagen die Agenten Vorschläge mit 83 Prozent hinter den 86 Prozent zurück.

Zweitens verschiebt sich die Rolle des Entwicklers. GitHub formuliert es selbst so. Der erste Schritt ist für einen wachsenden Teil der Arbeit nicht mehr das Schreiben, sondern das Anweisen eines Agenten, und das Prüfen ist der Moment, in dem Entwickler formen, was zurückkommt. Dazu passt, dass die Nutzung von KI gestützter Codeprüfung und von GitHubs Sicherheitsangebot um mehr als 90 Prozent zugenommen hat. Und ein neues Werkzeug für gestapelte Änderungsvorschläge, also kleinere, aufeinander aufbauende Schritte, die leichter zu prüfen sind, wurde binnen zwei Monaten von 264000 Entwicklern ausprobiert.

Drittens ist die Modellwahl selbst unruhig geworden. Bei GitHub Copilot verteilten sich die Anfragen im September so. 38 von 100 gingen an Allzweckmodelle, 37 an Modelle für tiefes Nachdenken und Planen, 25 an schnelle kleine Modelle. 61 Prozent der Copilot Nutzer verwendeten mehr als ein Modell, und 63 Prozent der zahlenden Nutzer ließen mindestens einmal automatisch ein Modell auswählen. Wer Modelle einkauft, sollte das lesen als Abschied vom einen Modell pro Team. Es gibt jetzt eine Rotation.

Was heißt das praktisch? Für Teams, die Agenten einführen, ist der stärkste Einzelwert der Vergleich neuer Projekte. Wer in diesem Jahr ein Projekt mit einer Agenten Konfigurationsdatei angelegt hat, kam im Schnitt auf achtmal so viele Commits wie ein neues Projekt ohne. Das ist kein Beweis für achtmal so viel Produktivität. Aber es ist ein starkes Signal, dass die Konfiguration am Anfang den Unterschied macht, also die Frage, welche Regeln gelten, welche Werkzeuge erlaubt sind und wie geprüft wird. Nicht das Modell allein.

Für alle, die solche Zahlen weiterverwenden, gilt Vorsicht. GitHub zählt Commits, nicht Ergebnisse. Ein Agent, der eine Aufgabe in zwanzig kleinen Schritten erledigt, erzeugt zwanzig Commits. Ein Mensch, der dasselbe in einem Zug macht, einen. Wenn Agenten mehr und kleinere Änderungen einreichen, steigt die Kurve, ohne dass mehr Software fertig wird. GitHub weiß das und schreibt selbst, die Zahlen beschrieben beobachtete Nutzung, nicht Modellqualität. Eine zweite Einschränkung ist, dass der Bericht nicht im Detail verrät, wie Agenten Beteiligung erkannt wird. Es ist eine Schätzung auf Plattformdaten.

Ein Blick auf die Sicherheit lohnt auch. Der Schutz vor versehentlich hochgeladenen Passwörtern und Schlüsseln lief in diesem Jahr 5,8 Milliarden Mal, fast viermal so oft wie 2025. Gleichzeitig wurden über 30 Millionen automatische Aktualisierungsvorschläge von Dependabot übernommen, etwa doppelt so viele wie im Vorjahr. Mehr Code bedeutet also auch mehr automatische Pflege und mehr Prüfungen.

Und dann ist da noch die Grenze der Aussage. Der Octoverse ist eine Selbstdarstellung mit Daten. GitHub ist Anbieter von Copilot und verdient daran, dass Agenten mehr Arbeit übernehmen. Der Bericht ist so geschrieben, dass diese Entwicklung als Fortschritt erscheint. Nachprüfen lässt sich das nicht, weil nur GitHub diese Daten hat. Wer den Bericht liest, sollte ihn als gut dokumentierte Innenansicht nehmen und nicht als neutrale Messung der Softwarebranche. Immerhin legt GitHub die Methode offen, nennt die Definitionen und rechnet die Vorjahreswerte nach derselben Formel neu, statt alte Zahlen stehen zu lassen. Das ist mehr, als viele Branchenberichte tun.
