llama.cpp ist 1.0: Ein Versprechen an alle, die den Code einbinden

13.11.2026, 11:20 · #news #llm #benchmark #open-weights · GitHub (ggml-org)

Zum Anhören: 6:12 Minuten (KI-Stimme) – MP3 herunterladen (2,8 MB)

TL;DR

  • Das Team hinter llama.cpp hat am 13. November um 10:20 UTC die Version 1.0.0 veröffentlicht, zusammen mit der Tensor-Bibliothek ggml, die ebenfalls auf 1.0.0 geht. Der letzte Schliff steckt in einem Commit mit der Kennung b1b770d.
  • Die 1.0 ist vor allem ein Versprechen an alle, die die C-Bibliothek einbinden: Ab jetzt zeigt eine neue Hauptversion eine inkompatible Schnittstelle an. Dafür fallen 35 veraltete Funktionen und llama_set_warmup aus der öffentlichen Header-Datei.
  • Technisch bringt das Release FP8-KV-Cache Der Zwischenspeicher für den schon gelesenen Text. Ein Modell legt pro Token und Schicht ab, worauf es sich später beziehen muss; bei langen Unterhaltungen wächst dieser Speicher und wird zum Flaschenhals. Im Lexikons, einen Cache für die Experten von Mixture-of-Experts Bauweise, bei der ein Modell aus vielen Teil-Netzen besteht und pro Anfrage nur wenige davon rechnen. So bleibt ein sehr großes Modell bezahlbar. Im Lexikon-Modellen mit einstellbarem CPU-Anteil, einen OpenAI-kompatiblen Endpunkt für Sprachausgabe und einen gehärteten Server gegen SSRF, CORS und DNS-Rebinding.
  • Dreieinhalb Jahre nach dem ersten Commit Ein einzelner gespeicherter Änderungsschritt in einem Projekt, mit Zeitstempel, Autor und einer kurzen Beschreibung. Viele Commits zusammen ergeben die Geschichte einer Datei oder eines Programms. Im Lexikon stehen 134.862 Sterne, 25.553 Forks, 447 Beitragende und 2.604 offene Issues. Auf Reddit ist der meistgewählte Kommentar zum Jubiläum die Bitte um mehr Maintainer.
  • Ein Fork namens Strata, der auf demselben Code aufsetzt, schreibt in einem Community-Vergleich 2,4-mal schneller und liest Prompts 2,9-mal schneller. Der Vergleich stammt aus einem einzigen Issue-Thread mit einer Grafikkarte und einem Modell, ist also ein Hinweis und keine Beweislage.

Was ist passiert

Am 13. November um 10:20 UTC hat die Organisation ggml-org die Version 1.0.0 von llama.cpp veröffentlicht (Release). Zur selben Stunde ging ggml auf 1.0.0, die Tensor-Bibliothek, auf der die Inferenz Der Betrieb eines fertigen Modells: Anfrage hinein, Antwort heraus. Das Gegenteil von Training. Im Lexikon läuft. Der Blogbeitrag dazu steht bei Hugging Face, geschrieben von Daniel Bevenius, Georgi Gerganov, merve und weiteren Mitgliedern der Organisation (Hugging Face).

Der Anlass ist kein neues Modell, sondern die Verantwortung gegenüber denen, die den Code einbauen. "Jede neue Integration bedeutet mehr Entwickler, die von unseren Bibliotheksschnittstellen abhängen, und deshalb ist eine flexible, aber stabile API Die Schnittstelle, über die ein Programm ein anderes Programm aufruft. Bei KI-Diensten schickt die eigene Software eine Anfrage an das Modell und bekommt eine Antwort zurück, ohne dass ein Mensch im Chat mitliest. Im Lexikon entscheidend", heißt es im Blog. Konkret: Ein Wechsel der Hauptversion zeigt jetzt eine inkompatible C-Schnittstelle an, ein Wechsel der Nebenversion eine rückwärtskompatible Erweiterung, ein Patch eine Fehlerbehebung ohne Schnittstellenänderung.

Der Preis für diese Klarheit steht in den Release-Notes. 35 als veraltet markierte Funktionen, llama_set_warmup und der Parameter defrag_thold sind aus llama.h verschwunden. Wer eigene Anwendungen gegen die Bibliothek baut, muss diese Stellen suchen, bevor er aktualisiert.

Inhaltlich ist das Release kein reines Aufräumen. Die Quantisierung Ein Modell wird mit weniger Bits pro Wert gespeichert, etwa vier statt sechzehn. Das spart Speicher, kostet aber etwas Genauigkeit. Im Lexikon des KV-Cache Der Zwischenspeicher für den schon gelesenen Text. Ein Modell legt pro Token und Schicht ab, worauf es sich später beziehen muss; bei langen Unterhaltungen wächst dieser Speicher und wird zum Flaschenhals. Im Lexikons kann jetzt FP8 in der OCP-Variante, mit optionalen Skalen pro Tensor. Für MoE-Modelle gibt es einen Cache für Experten im Hauptspeicher, dessen CPU-Anteil sich einstellen lässt, mit zwei Verdrängungsstrategien. Dazu kommen das Nachladen externer Parameter-Shards, vier neue Architekturen (Kimi-K3.1-Pro, Ripple-65B-Preview, xing4_0 und die Sprachausgabe drama-3), ein Endpunkt /v1/audio/speech nach dem Muster von OpenAI und ein neu gebauter Web-Client für den Server. Sicherheitsrelevant sind vier Reparaturen: SSRF, CORS, DNS-Rebinding und der Abbruch von Werkzeugaufrufen über MCP.

Warum zählt es

Die Zahl 1.0 ist in der Softwarewelt eine Zusage, keine Leistung. Sie sagt, dass ein Projekt seine Schnittstelle für ernst genug hält, um sie zu versionieren. Für llama.cpp wiegt das mehr als bei den meisten Projekten: 447 Menschen haben Code beigetragen, das Repository hat 134.862 Sterne, und die Bibliothek ist die Grundlage für eine ganze Klasse von Anwendungen, die lokale Modelle auf Laptops, Servern und Einplatinenrechnern laufen lassen.

Der zweite Grund ist unangenehmer. Das Projekt trägt seit Monaten eine Debatte über sein Tempo mit sich, und die 1.0 hat sie nicht beendet. Im Reddit-Thread zur Veröffentlichung, mit 744 Punkten und 90 Kommentaren derzeit der sichtbarste Ort zum Thema, ist der bestbewertete Kommentar keine Gratulation, sondern eine Bitte: "Bitte fügt dem Projekt mehr Maintainer hinzu, es gibt buchstäblich eine Tonne offener Issues und Pull Requests" (Reddit). Ein Antwortkommentar mit 65 Punkten nennt den Grund für die Ungeduld: llama.cpp sei gegenüber Projekten wie Strata deutlich zurückgefallen, beim Nachladen von Gewichten von der SSD sei der Fork inzwischen weit vorn, und die Geschwindigkeitsgewinne kämen nicht mehr im Wochentakt.

Ein Beleg für die Wartezeit lässt sich nachprüfen. Der Pull Request, der das Modell Dory unterstützt, liegt seit dem 10. Oktober offen, ohne Zusammenführung, mit 20 Kommentaren (GitHub). Ein Modell, das in dieser Branche im Oktober interessant war, ist im November alt.

Der Gegenpunkt kommt im selben Thread und ist ebenfalls richtig. llama.cpp läuft auf Grafikkarten und Prozessoren, für die andere Engines keinen Code bauen. "Strata unterstützt keine alte Hardware wie llama", schreibt ein Kommentar, und ein anderer nennt die Container-Abbilder für CUDA, ROCm und SYCL als Grund, warum er bleibt: herunterladen, Modell daneben legen, starten. Die Spitze ist woanders, die Fläche ist hier.

Was heißt das praktisch

Wer llama.cpp in eine eigene Anwendung einbindet, sollte jetzt gegen 1.0 bauen und die Liste der entfernten Funktionen aus den Release-Notes abarbeiten. Danach zeigt jede Aktualisierung, ob sie bricht. Das ist der eigentliche Gewinn dieser Veröffentlichung.

Wer lokale MoE-Modelle fährt und dabei Speicher knapp wird, hat zwei neue Schrauben: moe_cache_size und moe_cache_cpu_share. Die Community-Messung oben zeigt aber auch die Grenze: Bei einer Karte, auf die das Modell vollständig passt, kostet der Cache rund zehn Prozent Durchsatz Wie viel Material eine Anlage in einer Stunde schafft — bei Sortieranlagen in Tonnen pro Stunde. Im Lexikon gegenüber dem normalen Laden, weil statt zwei Graph-Aufteilungen pro Token Das Wortstück, in das ein Sprachmodell Text zerlegt. „Roboter“ kann in „Robot“ und „er“ zerfallen. Rechenaufwand und Kontextlänge werden in Token gemessen. Im Lexikon fünfzig anfallen. Der Cache ist ein Werkzeug für den Fall, dass das Modell nicht passt, keine allgemeine Beschleunigung.

Wer das Maximum aus einer Karte herausholen will, muss messen statt annehmen. Die Zahlen aus dem Strata-Vergleich sind deutlich: 101 Token pro Sekunde gegen 43 bei einem Modell, das vollständig in den Speicher passt, und 3,4 statt 9,8 Sekunden bis zum ersten Token bei 4.096 Token Prefill Die erste Rechenphase einer Anfrage: Das Modell verarbeitet den gesamten Prompt auf einmal, bevor es das erste Wort der Antwort erzeugt. Bei langen Eingaben dauert dieser Schritt am längsten. Im Lexikon. Sie stammen aus einem Thread, einer Grafikkarte und einem Modell, mit drei Läufen pro Messpunkt und Temperatureinstellung null. Für eine Kaufentscheidung ist das zu wenig, für einen Test auf der eigenen Hardware ist es ein guter Anlass.

Wer auf neue Modelle angewiesen ist, sollte die Merge-Geschwindigkeit beobachten, nicht die Versionsnummer. Der Tag 1.0.0 ändert daran nichts: Was nicht zusammengeführt wird, fehlt in der Bibliothek, egal wie sauber die Schnittstelle versioniert ist.

Was die 1.0 nicht bedeutet

Die Versionsnummer sagt nichts über Stabilität im Betrieb. 2.604 offene Issues und eine Maintainer-Gruppe, die im Reddit-Thread um Verstärkung gebeten wird, bleiben bestehen. Der Blogbeitrag selbst nennt als Ziel, die Architektur zu beherrschen und die Codequalität hoch zu halten, nicht, schneller zu werden. Wer Tempo braucht, muss weiterhin Forks vergleichen.

Für die langfristige Planung ist die Verteilung der interessantere Teil des Releases. llama.cpp liegt als Paket für Homebrew, Debian, conda-forge, MacPorts, Winget und als XCFramework für Apple-Plattformen bereit, dazu Container und fertige Archive für Linux, macOS, Windows, Android und iOS. Ein Projekt, das diesen Aufwand betreibt, ist nicht auf dem Rückzug. Es hat nur Konkurrenz bekommen, die schneller ist und dafür schmaler.
